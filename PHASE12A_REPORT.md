## Implementation
Selected Supabase Auth with a future same-origin FastAPI backend-for-frontend and opaque browser cookie. Provider owns passwords/email/reset; future backend owns token storage/refresh and explicit authorization. Detailed design, additive migration/rollback plan, one-to-one association proposal, beta/SMTP requirements and Phase 12B/12C handover are in PHASE12A_AUTH_ARCHITECTURE.md.

Changes: app/config.py adds optional validated provider-origin/publishable-key/timeout settings and a default-false flag that rejects activation in Phase 12A. app/auth.py adds an inactive, stateless `/auth/v1/user` verifier and immutable minimal account context. Signature verification is delegated to the configured trusted Supabase service; decoded claims alone never authenticate. Require eligible issuer/audience/role/expiry/issued-at/not-before/UUIDs, verified non-anonymous matching user, bounded time/body and generic failure. Reject privileged keys and redirects. No new dependencies.

The utility is not imported/wired into existing request authorization. No routes, account UI, sessions, ownership writes, migrations, provider dashboard changes, live users/emails or account-linking code. Existing staging login, cookies, records, frontend and worker remain unchanged.

Files: app/config.py, app/auth.py, .env.example, tests/test_account_auth.py, this report and PHASE12A_AUTH_ARCHITECTURE.md.
